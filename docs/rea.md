# REA

`rea` is a reverse engineering CLI and MCP server. Run `rea setup` to review agent configuration changes; use RPM updates rather than `rea update`. Setup modifies user configuration only after approval. REA executes analysis tools with the user's privileges; inspect untrusted targets in an appropriate isolation environment. Ghidra and other analysis engines are separately installed and configured. Linux process ownership checks require `procps-ng`.

## Sources and build

- [Upstream installation](https://github.com/morluto/rea/blob/rea-agents-6.9.0/docs/getting-started/installation.md) recommends the published npm package. [Upstream release documentation](https://github.com/morluto/rea/blob/rea-agents-6.9.0/docs/development/releasing.md) describes testing the exact npm archive.
- The [Fedora Node.js guidelines](https://docs.fedoraproject.org/en-US/packaging-guidelines/Node.js/) prefer npm registry tarballs and require bundled license review. The npm archive contains generated JavaScript rather than TypeScript source; this personal COPR ships those upstream-generated files rather than rebuilding them. The [tagged repository](https://github.com/morluto/rea/tree/rea-agents-6.9.0) contains the corresponding source.
- The [AUR package](https://aur.archlinux.org/packages/rea-agents) exists, but its recipe was inaccessible behind an anti-bot challenge during research. No Fedora or COPR recipe was identified; this is not a definitive availability claim.

SRPM preparation checks `source.sha256`. RPM builds need network access to install the shrinkwrap's integrity-pinned npm dependencies, with lifecycle scripts disabled; no dependency cache is bundled in the SRPM. Packit jobs remain disabled; enable networking for a future test build. Only the `rea` command is installed, not its upstream `rea-agents` alias. Review upstream changes, dependencies, integrity pins, and applicable notices when updating.

The runtime includes upstream prebuilt `@lydell/node-pty` binaries and WASM from dependencies. These have not been independently rebuilt or audited. Frida is removed because its native binding requires an install step; Frida functionality is unavailable in this package. The npm tarball's Windows native binary is not installed. The runtime license inventory is generated from npm metadata and needs independent review, including shipped third-party notices. External engines and optional tools can have additional licensing and security requirements. Desktop-build integration invokes `python3`, and Hopper provisioning invokes `tar`; these optional features have further prerequisites that REA's doctor checks, so they are not required by the base RPM. The `sqlite` build dependency supplies the test fixture command; REA uses Node's SQLite support for that check.

## Updates and limitations

The 6.9.0 shrinkwrap pins `openpgp` 6.3.2. Its [npm archive](https://registry.npmjs.org/openpgp/-/openpgp-6.3.2.tgz) ships generated `dist` files and an LGPL license, not its source tree. The [v6.3.2 source](https://github.com/openpgpjs/openpgpjs/tree/v6.3.2) uses Rollup and additional dependencies to generate the distribution; see its [build configuration](https://github.com/openpgpjs/openpgpjs/blob/v6.3.2/package.json). The REA source link above is not a substitute for determining the corresponding source of this dependency and its bundled components. REA's shipped code uses dynamic `import("openpgp")`, which the npm package's Node export maps to `dist/node/openpgp.mjs`. That unminified bundle has no source map; upstream's [Rollup configuration](https://github.com/openpgpjs/openpgpjs/blob/5f33328a3b601fb9c9dce310d1ecc137db0dbc75/rollup.config.js) generates maps only for minified outputs. The npm archive contains 12 minified-bundle maps with embedded `sourcesContent` for every listed source, including some bundled dependencies. The spec retains the upstream distribution and checks those map entries during `%check`, but they do not directly map REA's imported file. The [v6.3.2 source revision](https://github.com/openpgpjs/openpgpjs/tree/5f33328a3b601fb9c9dce310d1ecc137db0dbc75) includes `package-lock.json` and the Rollup configuration. The npm archive matches REA's shrinkwrap integrity and its `package.json` is byte-identical to that source tag's, but neither establishes that the tagged inputs reproduce the shipped outputs or satisfy the source requirements. Neither the maps nor these references establish that all preferred source, build inputs, and instructions needed for the shipped files are available. The required materials, their availability to recipients, and the resulting LGPL obligations remain unverified; keep hosted builds disabled and do not redistribute until resolved.

REA uses OpenPGP.js to verify signed Hopper releases before provisioning. The checksummed upstream npm archive itself contains `package/node_modules/openpgp`, so removing it only from the binary RPM would still distribute it in the SRPM and would disable Hopper provisioning. A solution must address the source archive too and must never bypass signature verification. The import appears in `dist/process/DetachedPgpSignature.js` and in the bundled CLI and MCP Hopper implementations; this is not proof that every possible use has been identified.

## Validation

Upstream 6.9.0 accepts Node.js `^22.23.4 || ^24.22.1 || >=26.12.1`. The RPM specifically requires Fedora's `nodejs24` >= `1:24.22.1` and invokes `/usr/bin/node-24`, avoiding an incompatible default Node stream. At research time Fedora 44 and 45 had compatible Node.js 24 builds in updates-testing, not stable; Rawhide had a compatible build. COPR build 11322134 confirmed that the required Node version was unavailable in stable Fedora 44 and 45; do not lower the requirement below upstream's supported range. A Fedora 45 x86_64 query of enabled repositories still returned 24.18.0; enabling `updates-testing` for the query returned 24.22.1. That does not establish availability in the default COPR buildroot or on other targets. Rawhide reached RPM packaging but failed on an empty debugsource package for prebuilt binaries; the spec disables debugsource generation for those inputs. Rebuild to verify that adjustment. Check enabled repositories and the source-builder runtime for each target. The RPM has not been built successfully on Fedora or validated on either architecture. A local offline npm install, CLI startup, and small JavaScript analysis were checked on macOS, not Fedora. These do not verify MCP sessions, setup, Linux native PTY behavior, or external analysis engines.
