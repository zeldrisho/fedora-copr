# Pi coding agent

`pi-coding-agent` provides the `pi` CLI. Fedora also ships a package with this name; this COPR tracks newer upstream releases. Pi runs commands with the user's permissions and has no built-in permission sandbox. Configure a provider with `/login`; see [upstream documentation](https://github.com/earendil-works/pi/tree/v1.5.2/packages/coding-agent). Use RPM updates rather than `pi update` to maintain the system installation.

## Sources and build

- The [upstream README](https://github.com/earendil-works/pi/tree/v1.5.2) specifies Node.js 22.19 or newer and recommends disabling npm lifecycle scripts.
- The [npm release](https://registry.npmjs.org/@earendil-works/pi-coding-agent/1.5.2) provides upstream's compiled JavaScript and model catalog. This replaces the previous source-built workspace and is not equivalent to rebuilding it from Git.
- The [Fedora Node.js guidelines](https://docs.fedoraproject.org/en-US/packaging-guidelines/Node.js/) and [Fedora's existing spec](https://src.fedoraproject.org/rpms/pi-coding-agent/blob/rawhide/f/pi-coding-agent.spec) inform the package layout and license inventory. Unlike the Fedora spec, this package builds the Linux clipboard helper and retains image processing and QuickJS WASM.
- The [Fedora debuginfo guidelines](https://docs.fedoraproject.org/en-US/packaging-guidelines/Debuginfo/) recommend retaining symbols and compiler flags. The local patch removes upstream's strip and hard-coded optimization flags from the [Linux helper build](https://github.com/earendil-works/pi/blob/v1.5.2/packages/tui/native/linux/build.sh), and passes RPM compiler and linker flags instead. COPR build 11321058 failed because the stripped helper left an empty debugsource package.

SRPM preparation verifies the npm archive and separately supplied license inputs using `checksums.sha256`. The RPM build resolves npm dependencies over the network with lifecycle scripts disabled. There is no maintained local lock or dependency cache; transitive versions may change between builds, so builds are less reproducible and depend on the registry.

## Validation and limitations

The launcher uses the npm release's unbundled `dist/cli.js`; the upstream `dist/bundle` and examples are removed from the binary RPM because the bundle drops legal comments and examples include prebuilt binaries. They remain in the upstream npm tarball used as an SRPM input and also need review before any hosted build. A local macOS Node test of the unbundled CLI passed version and offline empty package listing checks. This is still generated JavaScript, not a source build; it retains vendored HTML export scripts and precompiled WASM, including QuickJS extension modules whose filenames end in `.so`. QuickJS's crypto extension uses mbedTLS; Photon includes compiled Rust dependencies. The RPM inventory lists installed lockfile packages, their declared licenses, and whether a root-level license or notice file is present; it does not establish their complete provenance or license obligations. A local `npm ci --omit=dev --ignore-scripts` audit found 123 installed lock entries and 14 without a root-level notice; that count is a review lead, not proof of a missing license, and may differ on Fedora. In an earlier recipe with a committed lock, all 123 registry archives were downloaded without installation and checked against their lock integrity values; this historical scan does not describe the current unlocked build: 14 lack root-level license/notice files. These include eight Pi workspace packages covered by the separately included project license, `data-uri-to-buffer` (notice in its README), `standardwebhooks` (separately included license), three AWS SDK packages, and `proxy-agent-negotiate`. The three AWS packages declare Apache-2.0. Matching upstream release-commit package manifests identify [credential-provider-http 3.972.86](https://github.com/aws/aws-sdk-js-v3/blob/dee2abd898e7d1c69dd5ca5d74ecdce92e47d19d/packages-internal/credential-provider-http/package.json), [nested-clients 3.998.3](https://github.com/aws/aws-sdk-js-v3/blob/dee2abd898e7d1c69dd5ca5d74ecdce92e47d19d/packages-internal/nested-clients/package.json), and [credential-provider-login 3.972.92](https://github.com/aws/aws-sdk-js-v3/blob/5b4a724f2ac4006ea5a98c2fed6c629f6845b9bd/packages-internal/credential-provider-login/package.json); the root license is identical at both commits and is included separately. The root and these package directories have no separate NOTICE at those revisions. These matching versions are evidence, not independent npm provenance or a complete embedded-code audit. This archive scan includes packages that may not be installed on a given architecture and does not audit embedded code. Native clipboard helpers are built from source for the target architecture. Provider authentication, actual model access, extensions, image resizing and clipboard behavior need manual testing; the RPM build checks startup, an offline empty package listing, Photon image decoding, QuickJS evaluation, and native module loading. npm and optional tools installed by Pi or users may access the network at runtime. Packit PR and main publishing jobs are disabled after [build 11324034](https://copr.fedorainfracloud.org/coprs/build/11324034/) failed: npm did not install `pi-tui` in the expected `runtime/node_modules` directory. The spec now creates a separate npm project there; the change still needs Fedora build validation.

## Bundled components and notices

References for this audit include the [upstream bundle build](https://github.com/earendil-works/pi/blob/v1.5.2/scripts/build-coding-agent-bundle.mjs), [quickjs-wasi 3.6.2 source](https://github.com/vercel-labs/quickjs-wasi/tree/5a7a0eeda87c99542f8cf3095b6d61ecfa755977), and [Photon source](https://github.com/silvia-odwyer/photon). The spec supplies hash-pinned copies of the mbedTLS license from that source and the QuickJS-NG license from its pinned submodule. Its amalgamated Ada URL header identifies version 3.4.3, so the corresponding MIT license is included too. The `standardwebhooks` 1.1.1 npm archive omits its MIT license, so the spec also includes the license from its published Git revision. The Pi workspace packages share the separately included upstream project license; `data-uri-to-buffer` includes its MIT notice in its README. `proxy-agent-negotiate` declares MIT but its npm archive and tagged source omit a license file, leaving its precise copyright notice unresolved; upstream [issue #479](https://github.com/TooTallNate/proxy-agents/issues/479) requests the applicable text. The HTML exporter separately vendors Highlight.js 11.9.0, Marked 18.0.11, and marked-cjk-friendly 0.1.2, as identified by their installed file headers. The spec includes their license texts from SHA-256-pinned npm archives and checks those headers during the build; the installed Highlight.js 10.7.3 dependency alone does not cover the separate export copy. The [Fedora Node.js guidance](https://docs.fedoraproject.org/en-US/packaging-guidelines/Node.js/#_bundled_licenses) applies the license review to generated JavaScript too; [Fedora's existing Pi spec](https://src.fedoraproject.org/rpms/pi-coding-agent/blob/rawhide/f/pi-coding-agent.spec) is a layout reference, not an audit of these versions. Ada's embedded third-party code, WASI runtime components, Photon dependencies, the contents of vendored export scripts, and other bundled artifacts still need an independent audit; these references are not a completed review.

The [quickjs-wasi 3.6.2 build](https://github.com/vercel-labs/quickjs-wasi/blob/5a7a0eeda87c99542f8cf3095b6d61ecfa755977/Makefile) uses WASI SDK 32, links WASI emulation libraries, and explicitly links libc++ code into the URL extension. The SDK 32 source pins [wasi-libc](https://github.com/WebAssembly/wasi-libc/tree/2fc32bc81b9f07f8d9525edea59bfbaf760c06d6) and [LLVM](https://github.com/llvm/llvm-project/tree/4434dabb69916856b824f68a64b029c67175e532). The spec includes pinned wasi-libc, musl, cloudlibc, and LLVM license texts and provisionally adds `Apache-2.0 WITH LLVM-exception` for libc++; the [wasi-libc license overview](https://github.com/WebAssembly/wasi-libc/blob/2fc32bc81b9f07f8d9525edea59bfbaf760c06d6/LICENSE) describes additional third-party portions. These build instructions and notices are evidence, not proof of the exact linked contents or complete notice coverage of the published WASM. Confirm artifact provenance and remaining embedded components before publication.

For Photon, npm metadata for `@silvia-odwyer/photon-node` 0.3.4 reports Git revision [`685f5b1`](https://github.com/silvia-odwyer/photon/tree/685f5b155b36c5611c08ca678bb78ddbab3edbac). At that revision, the [Rust crate manifest](https://github.com/silvia-odwyer/photon/blob/685f5b155b36c5611c08ca678bb78ddbab3edbac/crate/Cargo.toml) identifies itself as 0.3.3 and declares dependencies including `image`, `imageproc`, and `palette`; there is no committed `Cargo.lock` in the repository tree. The npm archive ships a compiled WASM module and the project Apache-2.0 license, not a pinned Rust dependency inventory. The metadata revision and manifest therefore do not establish the exact sources or dependency licenses in that WASM. [Fedora's Rust license guidance](https://docs.fedoraproject.org/en-US/packaging-guidelines/Rust/#_license_tags) highlights the need to account for linked crates; obtain authoritative build inputs or rebuild from reviewed, pinned source before treating this artifact's audit as complete.
