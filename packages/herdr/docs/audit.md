## Source bundle contents and preliminary license findings

The Zig cache contains `translate_c`, Aro, `uucode`, Pixels, zlib, Wuffs, Highway, and the pinned `iterm2_themes` source archive. COPR build 11170443 failed in Fedora 44, Fedora 45, and Rawhide because Zig attempted to resolve `iterm2_themes` from the network, even though `emit_themes` is disabled for `-Demit-lib-vt`. The cache now includes that exact archive so dependency resolution can remain offline. The archive contains theme data and no filenames matching `license`, `copying`, or `readme`; its license/provenance still requires assessment as part of the outstanding complete source/license audit. Verify that no additional dependencies are downloaded in a clean, network-disabled build.

Preliminary notices indicate Pixels test/image data includes CC0-1.0; zlib has its own license and a separately licensed Boost-licensed contribution; `uucode` is MIT; Wuffs has MIT and Apache-2.0 notices; Highway has Apache-2.0 and BSD-3-Clause notices. These observations are not a completed inventory. Determine whether the relevant files/code are copied, compiled, linked, or otherwise included in the RPM, and assess license obligations for the source archives as a whole. Do not infer permissibility or the complete SPDX expression from filenames or an automated scanner.

The `0.9.5-2` RPM from COPR build 11170844 was inspected. It reports the spec's SPDX expression and installs the Herdr executable, manual page, README, Bash/Zsh/Fish completions, `LICENSE.dependencies`, `cargo-vendor.txt`, and the separately extracted Highway, uucode, and Wuffs notices. The RPM also has Cargo `bundled(crate(...))` Provides. No `bundled(...)` Provides for the native Zig/Ghostty components were identified in the RPM Provides; determine which native components are actually incorporated and whether Fedora requires declarations for them.

Inspection found that `%license LICENSE` and `%license vendor/libghostty-vt/LICENSE` collided at `/usr/share/licenses/herdr/LICENSE`. The actual RPM contained Ghostty's MIT license text (SHA-256 `386211873e5b7a02f663ae4d7adf96285999f91608f8f9f31fecfd0f4095e6f1`) and omitted Herdr's Apache-2.0 text (SHA-256 `c71d239df91726fc519c6eb72d318ec65820627232b2f796219e87dcf35d0ab4`). The `0.9.5-3` spec now stages the latter and the Ghostty notice at distinct names. This is a non-user-facing license-content correction; Release `3` is retained only because `0.9.5-2` has already been published with different RPM contents, and its NVR must not be reused. This fix passed SRPM/repository validation and was submitted as COPR build [11171377](https://copr.fedorainfracloud.org/coprs/zeldrisho/packages/build/11171377/) for a network-disabled Rawhide binary build; the RPM inspection is pending.

The fedora-review license scan for `0.9.5-2` reported 18,419 unknown files and assorted recognized license texts. That count is not evidence that files are unlicensed, but the file/source-level audit is not complete. In particular, Pixels CC0 data, zlib and its separately licensed contribution, `iterm2_themes` theme content, enabled Ghostty features, native linked code, exact bundle declarations, and the complete SPDX expression still require evidence-based assessment. Do not treat the current expression as final or declare the package ready until these questions and all source notices are resolved.

## Build and test status

COPR build [11170844](https://copr.fedorainfracloud.org/coprs/zeldrisho/packages/build/11170844/) succeeded on Rawhide x86_64 for `0.9.5-2` in the maintainer-reported 52 minutes. Its builder task states `enable_net: false`; the log shows test execution, version/completion checks, and RPM generation. This is clean Rawhide, network-disabled build/test evidence for `0.9.5-2`, not for the corrected `0.9.5-3` package. Its fedora-review invocation used `--prebuilt`, and its purported install check failed to install the RPM, so it is not an independent reviewer build or valid install test.

The build produced `herdr`, `herdr-debuginfo`, and `herdr-debugsource`. Local rpmlint on its SRPM and all three binary RPMs plus the spec reported zero errors; its only unique warnings were `invalid-url` on local Source1 and Source2, repeated when linting the SRPM. Preserve the downloaded, unmodified outputs outside the repository at `/tmp/herdr-11170844/fedora-rawhide-x86_64/`; obtain and retain final outputs for `0.9.5-3` before relying on them.
