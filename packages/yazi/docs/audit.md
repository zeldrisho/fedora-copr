# Yazi packaging audit

## Sources and build

- Upstream release: [v25.5.28](https://github.com/sxyazi/yazi/releases/tag/v25.5.28).
- `Source0` is the upstream source archive; `Source1` is the checked-in Cargo vendor archive so SRPM builds and tests work offline. `Source2` is the SSH syntax repository snapshot at [commit `e1012e9`](https://github.com/robballou/sublimetext-sshconfig/commit/e1012e9f13c6073f559b14206df2ede35720e884); `Source3` is its GPL text from [commit `a47c765`](https://github.com/robballou/sublimetext-sshconfig/commit/a47c765aa14d58236b5e5964bb687b5352450547); `Source4` is the source and notice archive for the filtered syntax set.
- Fedora 44 does not provide all required crate versions/features. The spec uses the Fedora Rust vendoring macros and emits `cargo-vendor.txt` for bundled-crate provides.
- The spec removes prebuilt object/library files from the vendor tree before building, and clears executable bits from Rust sources to avoid false shebang processing in RPM debug sources.
- Lua and Oniguruma use the Fedora system libraries. The Yazi feature patch disables upstream's vendored Lua defaults; `RUSTONIG_SYSTEM_LIBONIG` and `RUSTONIG_DYNAMIC_LIBONIG` direct Oniguruma to the system library.

## Licensing

- Yazi's own source license is MIT.
- `LICENSE.dependencies` is generated by `%cargo_license` during the build. The binary `License:` expression includes the cargo license-summary expressions plus syntax-content licenses.
- Yazi depends on `yazi-prebuilt`, whose crate metadata is MIT. Its generated syntax database is data rather than an executable; the crate README credits [bat](https://github.com/sharkdp/bat), and its `.gitmodules` lists 69 syntax repositories. The published crate's `.cargo_vcs_info.json` pins the prebuilt repository at `2d52c0b8b399aa476bfeff36a6256cffe76eb2a5`.
- A comparison with the submodule tree in bat v0.25.0 found 47 of Yazi's 69 pinned syntax-repository commits also present in bat. Five grammars are omitted from the package database: hosts and LiveScript because their pinned source repositories are unavailable; LESS and Verilog because no license grant was found; and Nginx because its pinned source is unavailable. Source4 archives the remaining 64 syntax sources with their pins and license/notice files. The checked-in Rust helper filters those five definitions from the published `yazi-prebuilt` database using syntect 5.2.0, preserving the other 200 compiled definitions and validating that the result loads through syntect's runtime API. The GPL-3.0-only SSH grammar is retained; its pinned source and license are included in Source2 and Source3, and the license is installed in the binary RPM.
- Fedora Legal explicitly reviewed the Sublime Text Packages license in [license-data issue #516](https://gitlab.com/fedora/legal/fedora-license-data/-/work_items/516), marked it `license::allowed` / `UltraPermissive`, and merged [MR !574](https://gitlab.com/fedora/legal/fedora-license-data/-/merge_requests/574) to record its exact permission text for `rust-bat`, `rust-syntect`, `rust-syntect4`, and `rust-two-face`. The package's `syntaxes/official` snapshot is pinned at `0a97be539c2732d7258ba4ec1450f7a3f4881b73c`; its upstream `LICENSE` is included in Source4 and aggregated into `LICENSE.syntaxes`. This supports `LicenseRef-Fedora-UltraPermissive` for the first-party Sublime content in Yazi's bundled database. The determination does not cover the other syntax repositories; those are accounted for separately using their pinned licenses and notices, with the shared inventory cross-checked against Fedora's [`rust-bat` spec](https://src.fedoraproject.org/rpms/rust-bat/raw/rawhide/f/rust-bat.spec). `LICENSE.syntaxes` and the source archive are installed in the RPM.
- Source checksums: vendor archive `ca9b28c5f6bfe7cc98bd421a8512c21fe262ef3e249bbe1413c93f2a8ddeda17`; filtered syntax database `0a002d918349f3df22ba8f6c0dd57d54f6af00d0307fb4efd6022232ee13e042`; syntax-source archive `2e1f77937fd9d1ec4956b0959c5c7dc2325bac141e13f51b693d3788d6368147`; SSH syntax archive `d13c5c410d976cf0c6fe52e2d0317a966bcf0899603b66e3e92b1bd5c7b24100`; GPL license text `5bcea00646cd676b4276fd75aaf3a4d42e438333714454f13d12469b8b949088`.

## Local verification

- `scripts/validate.py` generates and rpmlints the SRPM.
- Binary RPM built successfully on Fedora 44; Cargo build and test phases ran with the network disabled by the RPM Cargo setup.
- `yazi --version` and `ya --version` were smoke-tested after installing the RPM. RPM dependency metadata resolves `liblua-5.4.so` and `libonig.so.5` from Fedora packages.
