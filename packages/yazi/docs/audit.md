# Yazi packaging audit

## Sources and build

- Upstream release: [v26.9.1](https://github.com/sxyazi/yazi/releases/tag/v26.9.1), tag commit `8dd895c695a5950330c2623eb43debf323b60654` (GitHub reported a verified signature when checked).
- `Source0` is the upstream release archive. `Source1` is the checked-in Cargo vendor archive; it includes the forked ratatui Git dependency and allows offline builds. `Source2` is the SSH syntax repository snapshot at [commit `e1012e9`](https://github.com/robballou/sublimetext-sshconfig/commit/e1012e9f13c6073f559b14206df2ede35720e884); `Source3` is its GPL text from [commit `a47c765`](https://github.com/robballou/sublimetext-sshconfig/commit/a47c765aa14d58236b5e5964bb687b5352450547); `Source4` contains sources and notices for the filtered syntax set.
- The pinned `yazi-prebuilt` crate has checksum `33232d9116df6415ddfcdf72701b1b7439ce87f240a14723e8dd5d17e7ed5f98` and pins prebuilt repository commit `2d52c0b8b399aa476bfeff36a6256cffe76eb2a5`.
- The syntax database filter helper uses syntect 5.3.0, matching the upstream workspace. It removes syntax definitions for hosts, LESS, LiveScript, Nginx, Verilog, Fortran, F#, INI, Jinja2, Racket, and Todo.txt. The source archive excludes the six additional pinned repositories lacking adequate redistribution provenance. Strace's explicit README MIT grant is aggregated into `LICENSE.syntaxes`.
- The spec disables default vendored-Lua features and uses system Lua. Fedora 45 and Rawhide select mlua's Lua 5.5 feature; Fedora 44 selects Lua 5.4 and applies a compatibility patch replacing the Lua 5.5-only `create_external_string` API with the copying `create_string` API.
- `Source1` is prepared by `cargo vendor`; the checked-in archive removes prebuilt object/library files and updates Cargo checksum manifests accordingly. The spec also clears executable bits from Rust source files before `%cargo_prep`.
- Upstream requires Rust 1.95.0. Completion generation is enabled at build time and Bash, Fish, and Zsh completions are installed. The Fedora patch makes upstream's `VERGEN_GIT_SHA` override effective in exported source archives; the spec sets it to the verified upstream tag commit so `yazi --version` and `ya --version` retain meaningful revision metadata without a Git checkout.
- Checked the Homebrew and Termux 26.9.1 packaging examples. Their completions and `YAZI_GEN_COMPLETIONS` handling informed the Fedora install lists; Termux's `VERGEN_GIT_SHA` setting exposed the need for the Fedora patch, since upstream vergen otherwise emitted its idempotent placeholder. Android-only vendor pruning/patches were not adopted. Upstream's installation docs mark `file` as required and the preview/search/archive tools as optional; the spec uses `Requires: file` and Fedora `Recommends` for available optional tools. Clipboard tools remain optional alternatives and are documented rather than all weakly installed.

## Licensing

- Yazi's own source license is MIT. The spec `License:` expression now includes every alternative reported by `%cargo_license_summary` (including BlueOak-1.0.0 and CDLA-Permissive-2.0) plus the audited syntax-data and SSH grammar terms. The generated `LICENSE.dependencies` is installed with the RPM.
- `LICENSE.dependencies` is generated by `%cargo_license` during the RPM build.
- `yazi-prebuilt` is MIT metadata; that metadata does not establish redistribution permission for every grammar in its syntax database. Five existing exclusions remain: hosts, LiveScript, and Nginx have unavailable source snapshots; LESS and Verilog lack verified license grants. Six additional sources are excluded conservatively: Fortran, F#, Jinja2, Racket, and Todo.txt have no verified redistribution grant at their pinned snapshots, and the INI README attributes material to an unidentified internet source. Their compiled definitions and source trees are omitted.
- The GPL-3.0-only SSH grammar is retained; its pinned source and license are included in Source2 and Source3, and the license is installed in the binary RPM.
- Fedora Legal explicitly reviewed the Sublime Text Packages permission in [license-data issue #516](https://gitlab.com/fedora/legal/fedora-license-data/-/work_items/516) and merged [MR !574](https://gitlab.com/fedora/legal/fedora-license-data/-/merge_requests/574) to record its exact permission text. The package's `syntaxes/official` snapshot is pinned at `0a97be539c2732d7258ba4ec1450f7a3f4881b73c`; its upstream `LICENSE` is included in Source4 and aggregated into `LICENSE.syntaxes`. The determination does not cover the other syntax repositories, which are accounted for separately using their pinned licenses and notices.

## Syntax source license inventory and exclusions

The packaged source archive excludes Fortran, F#, INI, Jinja2, Racket, and Todo.txt because no sufficiently clear redistribution provenance was established from the pinned material. The INI README specifically says material was copied from an unidentified internet source. These are conservative packaging exclusions, not conclusions about the legal status of the upstream projects. The SSH snapshot remains separately covered by the pinned source and GPL text/notice. The official Sublime Text sources' Fedora Legal determination does not extend to other repositories.

The excluded source pins are recorded in the archive's provenance README: Fortran `315234/SublimeFortran` (`dcf4f24f1cecd9eebf6b1eb388e4f5db671a7b08`); F# `hoest/sublimetext-fsharp` (`9e4645c6085871d6fe4ae8dbcbafe93cb155b074`); INI `clintberry/sublime-text-2-ini` (`8dd3e316ada5cc8bffd3982bc2a9384345729f34`); Jinja2 `Martin819/sublime-jinja2` (`45355633d17ee562481ca1d2ad0e3502c238f58a`); Racket `follesoe/sublime-racket` (`7df4479c079768edd994b20052761152e277af21`); Todo.txt `dertuxmalwieder/SublimeTodoTxt` (`071a004217f981152c78dc7a530536374a753d98`). Strace `djuretic/SublimeStrace` (`3ec51e0bca39bf60cab7f96cecfc5d003c3ea59`) remains included because its README contains an explicit MIT grant; the generator now fails if that grant section disappears and places it in `LICENSE.syntaxes`.

The six flagged grammars and source trees have been removed conservatively pending verifiable grants and provenance. Reconsider an exclusion only after verifying permission at the exact source pin; regenerate from the original database and refresh license metadata, notices, checksums, and package release.
